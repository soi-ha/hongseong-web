# 홍성 아이디어북

Astro + TypeScript 기반 내부 검토용 정적 사이트. **2026-10-27 현재 배포본의 메인 `/`은 아이디어 페이지**다. 기존 제안서 페이지·메뉴는 공개 화면에서 제외했으며 뷰어 코드는 `src/archived/ProposalPage.astro`에 보존했다. 최종 PDF v4.03 원본은 모든 페이지의 헤더에서 자료조사 옆 **PDF 다운로드**로 바로 저장할 수 있다. 자료조사16개 주제와 내부 상세·출처 토글까지 배포했으며 GitHub `main`에도 기능별 커밋을 push했다.

**현재 배포 — 2026-10-27 전체 반영:** 최신 아이디어 홈·A안·관광 랠리·홍성 패스와 자료조사16개 상세를 모두 공개 사이트에 반영. 홈의 기존 정책 토글·설명 아래에 원문별 정책 해설 카드3개를 배치하고, B안 참고사례 카드2개와 패스 환급 안내도 내부 상세로 연결. 자료 상세의 출처는 기본 접힘 토글이며 원문 링크는 그 안에서 같은 탭으로 이동한다. 관광 랠리의 홍성스카이타워 대표 사진·궁리항 코스 사진·홍주읍성 사진, PDF v4.03(32쪽), 중앙 본문·우측 목차를 유지한다. ‘아이디어 개요’ 재배치는 미적용.

**자료조사 공개 상태:**16개 주제·고유 주소의 상세16개·출처 기록44건(기존 출처3건을 신규 정책 상세에서도 참조). 기존10개 주제 보존, 정책/환급 분리, 랠리 사례2개와 정책 원문별 상세3개 포함. 이전 배포의 ‘준비 중’ 화면을 교체했다. 앞으로의 후속 변경은 다시 localhost 검토 후 해당 변경의 별도 배포 요청에 따라 반영한다.

2026-10-27 관광 랠리 사진: 사용자 지정 최종 PDF v4.03의15쪽 홍성스카이타워·21쪽 홍주읍성 내장 사진을 직접 추출해 반영했다. 후속 사용자 요청으로 스카이타워를 상세 메인과 홈 B안 카드의 대표 사진으로 교체하고 여행 소개(`concept`)의 중복 사진을 제외했다. 기존 궁리항 진입부 사진은 당일 코스(`flow`) 설명 아래로 이동했으며 홍주읍성은 관광지·방문 인증(`places`)에 유지했다. 본문 문구는 유지했다. 사진 전체 비율을 보존한 최대 너비1600px WebP로 제공하며 새 파일2개 합계685,782바이트. `proposal-photos.json`에 PDF 해시·페이지·이미지 객체·추출 이미지 해시·기존 출처와2026-10-26 사용권 확인 기록을 연결했다. 새 사진의 제공자·공공누리 제1유형은 캡션에 표시하며 출처 링크·사용정보 토글은 추가하지 않았다. 타입 검사·정적 빌드·콘텐츠 검사와 PDF 변환기의 `--verify-only` 통과. localhost Chrome1728px·390px에서 사진·캡션·목차 이동과 가로 넘침 없음 확인. 빌드는 로컬 환경설정 쓰기 제한을 피하도록 해당 실행에만 `ASTRO_TELEMETRY_DISABLED=1` 적용.

아이디어 홈은 기획 의도 → 프로그램 참여·숙박 선택·공통 패스 흐름 → A·B안 사진 카드 → 공통 홍성 패스 → 정책 연결로 구성한다. 궁리 체험 코스(A안)·홍성 관광 랠리(B안)과 숙박 선택 이후의 공통 패스를 설명하며 상세3개를 유지한다. A안·패스의 기본 기획은 PPT v4.01, B안과 관련 연결 문구는 사용자 지정 웹 반영 원고 v02를 기준으로 한다. 홈·상세 본문은 기존 읽기 폭으로 중앙에 두고 여유가 있을 때만 바깥 오른쪽에 섹션 목차를 표시한다. 목차와 본문 사이 간격은 현재 검토값40px이며106rem 이하에서는 상단 가로 목차로 전환한다. 기존 `/ideas/`는 홈으로 연결한다. 사용자 지정 문구와 삭제 항목을 반영했다. A안·공통 패스의 기존 목표 수치는 유지하며, B안의 과거 수치·설명은 원고에 없는 내용이므로 승계하지 않았다.

사이트 이름은 2026-10-24 사용자 선택에 따라 **홍성 아이디어북**으로 통일했다. 이름·사이트 메뉴·메뉴 타입·파비콘 URL은 `src/config/site.ts`에서 관리한다. 현재 탭은 `아이디어 | 홍성 아이디어북`, `자료조사 | 홍성 아이디어북`, 상세는 `아이디어 제목 | 홍성 아이디어북` 형식이다. PDF 정보는 `src/content/proposal-slides.json`을 공통 헤더에서 참조한다.

파비콘은 투명 배경에 기존 포인트색 `#0380B7`로 책장이 펼쳐지고 넘어가는 움직임을 표현한 비대칭 심볼이다. 2026-10-24 참고 이미지의 굵은 실루엣·유기적인 곡선을 반영하고, 후속 피드백에 따라 눈·얼굴 표현을 제외했다. 같은 날 사용자가 수정본을 승인하고 배포를 요청했다. `public/favicon.svg`를 헤더 제목 왼쪽에도 함께 사용하며 `favicon.ico`에16·32·48px 변형을 담았다. 외부 서체나 이미지 없이 구성했으며 SVG 수정 시 ICO와 `src/config/site.ts`의 파비콘 캐시 버전도 함께 갱신한다. 새 아이콘을 홍성의 공식 브랜드 로고로 지정한 것은 아니다.

확인 당시 Astro의 Node 요구 조건은 `>=22.23.4`, Wrangler는 `>=22.0.0`. 이 저장소의 Node 허용 범위는 `package.json`에 명시했다. Node 26은 현재 Current 계열이며 LTS가 아니다. Node 24.22.1 LTS도 허용 범위이나 이번 실행 검증은 Node 26.9.0에서만 수행했다. 전역 Node·npm·Git 설정은 변경하지 않았다.

TypeScript `latest`는 7.0.2였지만 `@astrojs/check@0.9.12`의 peer 지원 범위가 `^5.0.0 || ^6.0.0`이므로 6.0.3 사용. 직접 의존성은 정확한 버전으로 고정하고 전체 의존성은 `package-lock.json`으로 관리한다. npm 설치 스크립트는 확인한 `esbuild@0.28.2`, `workerd@1.20261019.1`만 `allowScripts`에 명시했다.

## 로컬 실행

이 README가 있는 `hongseong-web` 폴더에서 실행한다. 2026-10-24 사용자 요청으로 기존 `honeseong-web` 철자를 정정했다. IDE와 터미널도 새 폴더에서 연다.

```sh
node --version
npm --version
npm ci
npm run dev
```

기본 주소: <http://127.0.0.1:4321/>. nvm을 이미 사용하는 환경에서는 설치 전에 `nvm install` 및 `nvm use`로 `.nvmrc`를 적용할 수 있다. nvm 자체는 이번에 설치하지 않았다. 환경 변수나 비밀값은 현재 필요 없으므로 `.env.example`도 만들지 않았다.

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | Astro 개발 서버, 기본 포트 4321 |
| `npm run check` | Astro·TypeScript 타입 검사 |
| `npm run build` | 정적 결과를 `dist/`에 생성 |
| `npm run check:content` | 빌드 후 최종 PDF·화면 자산·목차·다운로드 일치 및 전체 사이트 검사 |
| `npm run check:site` | 현재21페이지·기존 주소 리디렉션·내부 링크·자산·목차·자료 상세/레거시 앵커·헤더 다운로드 검사 |
| `npm run preview` | 빌드 결과의 Astro 로컬 미리보기, 기본 포트 4321 |
| `npm run preview:workers` | 빌드 결과의 Workers 로컬 미리보기, 포트 8787 |
| `npm run deploy:check` | 빌드·내용 검수 후 `wrangler deploy --dry-run`, 실제 업로드·배포 없음 |
| `npm run deploy` | 타입 검사·빌드·내용 검수 후 실제 Workers 배포. 사용자 배포 요청 시 실행 |

미리보기는 `npm run build` 후 실행한다. 개발 서버와 Astro 미리보기를 동시에 쓰려면 한쪽에 `-- --port 4322`를 붙인다. 모든 로컬 서버는 `127.0.0.1`에만 바인딩한다.

아이디어는 `src/content/ideas.ts`에서 편집한다. 사진은 기존 `proposal-photos.json`의 키를 연결해 출처·제공자·사용권 기록을 보존하며 이미지를 중복 복사하지 않는다. 사용자 요청에 따라 사진 출처 링크와 사용정보 토글은 화면에 표시하지 않는다. 상세의 사진은 원본 비율을 유지하고, 카드 썸네일은3:2 프레임의 하단 기준으로 표시한다. 기획 기준은 외부 프로젝트의 `문서/261026_홍성_관광객유치_제안_A안·B안_v4.01.pptx`이며 SHA-256은 `284a20c526f8dbd5c14c7b696b1d095f1798b4cc9ad870a9efaf7aca0ddccf33`이다. `IDEA_BASIS`에 PPT 기준 파일과 해시를 기록했다. B안은 외부 프로젝트의 `문서/261026_홍성_B안_관광랠리_웹반영원고_v02.md`를 우선하며 `RALLY_BASIS`에 원고 파일명·SHA-256·확인일을 별도로 기록했다. 상단 인계 정보는 화면에 표시하지 않는다. PPT와 자동 동기화되지 않으므로 원문 개정 시 명칭·표·수치·조건을 함께 대조한다.

목록은 짧은 소개·기획 의도 → 참여 흐름 → A·B안 사진 카드 → 숙박 선택 이후의 공통 홍성 패스 → 정책 방향 순서다. 사용자의 후속 정정에 따라 구조 설명은 유지하되, ‘두 프로그램을 즐기고 → 숙박 여부 선택 → 숙박 선택 시 공통 패스’의 짧은 흐름도로 분리했다. 후속 요청에 따라 각 단계를 연한 블루 박스로 표시하고 중앙의 큰 화살표로 연결한다. 흐름 안의 A/B 프로그램명과 홍성 패스 링크로도 상세에 이동할 수 있다. 사진·운영 시기·자세한 소개는 아래 소개 영역에서 제공한다. 정책 연결은 핵심 요약과 내부 정책 상세 버튼으로 제공한다. 일반 카드·설명·사진은 이동 영역이 아니며 흐름의 프로그램명 링크와 각 소개의 자세히 보기 링크에서 상세로 이동한다. 기존 상세 경로 `gungri-overnight`, `gungri-brand-meetup`, `hongseong-stay-pass`를 유지하고 화면 명칭만 최신안으로 변경했다. A안·패스의 운영 역할·성과 가정은 기본 HTML 펼침으로 제공하며, 정책 근거는 공통 자료 상세에서 읽는다. B안은 원고 전체를 펼쳐 읽으며 당일·1박 2일 각각의 제목과 목차를 사용한다. 목록·자료 상세 복귀와 목차·이전 주소 연결에 작은 클라이언트 스크립트를 사용한다. 목록에서 상세로 이동할 때 현재 위치와 눌렀던 링크의 고유 키를 탭별 sessionStorage에 기록하고, 상세의 ‘아이디어 목록으로’를 누르면 목록 위치·기존 버튼 포커스를 복원한다. 브라우저 뒤로/앞으로는 기본 복원 동작을 유지한다. 저장소 사용이 차단되거나 JavaScript가 꺼져 있어도 일반 링크로 이동할 수 있다. 복원은 애니메이션 없이 실행하며 버튼 색 전환은 움직임 줄이기 설정을 따른다. 모바일 표는 열 제목을 각 셀에 표시하는 세로 배치로 전환한다. 기획 기준·PPT 쪽수는 사용자 화면에 표시하지 않는다. 내부 대조 범위는 A안3~13쪽(목표표12쪽), B안은 웹 반영 원고 v02 전체(이전 PPT14~24쪽 기준 대체), 패스25~27·31~32쪽(연결표26·목표표27쪽), 정책28쪽이다. 기준 파일·해시는 `IDEA_BASIS`·`RALLY_BASIS`, PPT를 따르는 프로그램의 범위는 `sourcePages`에 보존한다. 후속 요청으로 지정된 안내 문구와 패스의 참고 사례·조사 수치 섹션을 제거했으며, 나머지 운영 조건과 성과 가정의 구분은 유지한다. 등록·수정용 관리자, 예약·결제·패스 발급 기능은 없으며 추가 예시 제작은 후속 요청 범위다.

현재 제안서 기준은 외부 프로젝트 `문서/261026_홍성_관광객유치_제안_A안·B안_v4.03.pdf`이다. 사용자 지정 PDF를 원본 그대로 보존한다. 실제32쪽·전부720×405pt(16:9)·회전0도, 원본4,929,975바이트(표시4.9 MB). SHA-256: `1e6e5f58f28e9c0979b91ea6d22dba585e531ed2263764432624edafc3359188`. 다운로드는 `/downloads/proposal-1e6e5f58f28e9c09.pdf`에서 동일 바이트를 제공하며 저장 파일명은 원본 이름을 사용한다. 원본 파일 이동·개명·수정, PPT 복사·업로드·재출력은 수행하지 않았다.

각 쪽은3840×2160px 무손실 WebP로 변환해 `public/slides/proposal-1e6e5f58f28e9c09/`에 보존한다. 이미지32장 합계15,895,644바이트. 별도 텍스트 제거·덮개·크롭·사진 보정 없이 전체 페이지를 렌더했다. 이미지 경로에도 내용 해시를 포함하며 모든 자산 검증 후 manifest를 교체한다. 이전 v4.01 PDF·화면 및 v03 자산은 보존한다. 현재 공개 페이지는 뷰어를 표시하지 않는다.

페이지 제목·목차는 v4.03의 실제 페이지를 대조했다. 표지1 → 목차2 → 개요3 → A안4 → B안14 → 패스·정책25 → 비교·추진29 → 수치와 출처31 → 클로징32. 기존 구간 앵커 `operation-a`·`results-a`·`operation-b`는 실제8·11·24쪽에 대응한다. 원본2쪽의 ‘수치·협의 조건31~32쪽’ 표기와 실제32쪽 클로징의 차이는 원본 그대로 유지한다. 뷰어 재사용 시 manifest의 실제 페이지 수·대응을 따른다.

슬라이드 하단 조작부에는 현재/전체 쪽수와 전체 화면·이전·다음만 배치한다. 뷰어는 첫 화면 높이를 유지하며 그 아래로 스크롤하면 독립된 ‘제안서 자료’ 섹션이 나타난다. 사용자 참고 이미지의 넓은 구역·제목·설명·구분선·파일 정보 배치를 적용하고 기존 서체·파란 포인트색을 유지했다. 자료 영역의 배경은 사용자 후속 요청에 따라 기존 블루 포인트 계열 `--color-accent-dark`(#026591)를 사용한다. 흰색 제목·안내·파일 정보와 흰 바탕/블루 글자의 버튼으로 대비를 확보하며 PDF 파일명·32쪽·4.9 MB와 ‘PDF 다운로드’를 제공한다. 모바일에서는 파일 정보 다음에 버튼이 이어진다. 전체 화면에서는 자료 영역을 숨겨 발표 공간을 유지하며 종료하면 다시 표시한다. 인쇄에서는 조작부와 다운로드 영역을 제외한다. 전체 화면 버튼 또는 `F`, 종료 `Esc`, 이동 `←`/`→`·`PageUp`/`PageDown`, 처음/끝 `Home`/`End`를 지원한다. 발표 중 `↑`/`↓`·`Space`/`Shift+Space`도 유지한다. 발표 조작부는2.2초 뒤 숨고 포인터·키보드 조작 시 다시 표시된다. 브라우저 전체 화면 미지원·거절 시 창 안 발표 모드로 전환한다. JavaScript가 꺼져 있으면 전체 페이지와 PDF 다운로드 링크를 이어서 표시한다.

현재 ‘출처’ 버튼·모달은 제외했다. 새 PDF 페이지에 이전 MD의 출처·주석을 번호만으로 대응시키지 않는다. PDF에 들어 있는 출처·주석·발표자 노트 참조 문구 등은 원본 그대로 표시하며 별도 조사를 통해 보충하지 않았다. 이전 모달 코드와 MD는 보존하지만 현재 제안서가 가져오지 않는다.

변환 도구는 PyMuPDF1.26.5·Pillow11.3.0을 기존 임시 환경에서 사용한다. npm 의존성은 추가하지 않았다. 현재 PDF의 재변환·검증:

```sh
python scripts/import-proposal-slides.py --pdf /path/to/final.pdf
python scripts/import-proposal-slides.py --pdf /path/to/final.pdf --verify-only
```

새 PDF는 직접 검토한 제목·목차를 JSON으로 준비해 `--metadata /path/to/reviewed.json`을 함께 지정한다. 필수 필드는 `version`, `sourcePdfSha256`, `slides[{number,title,label}]`, `groups[{id,label,from}]`이며 이전 구간 링크는 `legacyAnchors[{id,page}]`로 명시한다. 페이지 수·순서·크기·해시·전체 페이지 제목을 PDF와 대조하고 원본과 해시가 다르면 이전 metadata 재사용을 중단한다. `--verify-only`는 모든 WebP를 디코딩해 PDF 렌더 픽셀과 비교하고 다운로드 바이트를 원본과 대조한다. 최종 자산 정보는 기존 `proposal-slides.json` 한 곳에서 관리한다.

사용자가 2026-10-23 내부 검토용으로 사진 8장 사용을 지시했다. 원문에 기록된 사진 권리 확인 상태와 출처는 그대로 보존했으며 사용권 확보로 간주하지 않는다. 사진은 WebP(품질 86, 최대 너비 1600px, 확대·크롭 없음)로 변환해 합계 1,691,432바이트로 제공한다. 원본 워터마크도 유지했다.

검토본 표기와 `noindex, nofollow, noarchive`, robots 제외 요청을 적용했다. **검색 제외는 접근 제한이 아니다. 별도 로그인 없이 URL로 접근 가능하다.** 인증된 내부 공개 범위가 필요하면 별도로 접근 제어를 결정한다. React·SSR·Worker 처리 코드·DB·로그인·CMS·관리자 기능은 추가하지 않았다. 자료조사 카드·상세 영역은 로컬에 구현했다. 모달·PPT 다운로드는 추가하지 않았다.

메뉴명·사이트명·웹 세부 배치는 현재 구현값이다. 사용자 지정 색상·서체와 개별 웹 디자인의 최종 승인을 구분한다. 다른 사이트의 브랜드 자산은 복제하지 않았다. Workers는 정적 자산만 사용하며 `main`·서버 바인딩은 없고, Astro `trailingSlash: always`와 Workers `force-trailing-slash`를 맞췄다. SPA fallback·도메인 연결·GitHub 원격 생성·push는 수행하지 않았다.

## 보존한 제안서 뷰어 재사용

2026-10-26 사용자 요청으로 제안서 공개 페이지와 메뉴를 사용하지 않는다. 이전 페이지는 `src/archived/ProposalPage.astro`로 보관하며, `proposal-reader.ts`·`proposal-presentation.ts`·`proposal.css`와 manifest·PDF·전체 이미지도 유지한다. 공개 페이지에서 가져오지 않아 현재 HTML·JS/CSS 번들에 뷰어를 포함하지 않는다. PDF 다운로드는 공통 헤더에서 제공한다.

뷰어 복구가 요청되면 새 Astro 페이지에서 `ProposalPage`를 가져와 렌더링할 수 있다. 보존 페이지에는 `mainClass="proposal-main"`을 명시했고, 본문 다운로드 ID를 `archived-pdf-download`로 바꿔 헤더 ID와의 중복을 방지했다. 나머지 뷰어 본문·스크립트·스타일은 보존했다. 경로·사이트 메뉴와 `verify-site.mjs`의 공개 경로/뷰어 제외 검사는 새 요청 범위에 맞게 함께 조정한다. 렌더 복구 후에는 `node scripts/verify-proposal.mjs --viewer-html dist/proposal/index.html`처럼 실제 출력 경로를 지정해 현재 PDF32쪽·목차·조작부 검사를 실행한다.

기존 `/ideas/`는 Astro의 정적 리디렉션 페이지와 [Cloudflare `_redirects`](https://developers.cloudflare.com/workers/static-assets/redirects/) 규칙으로 `/`에 연결한다. `/ideas/{slug}/`는 그대로 사용하며 목록 복귀는 `/`에서 기존 위치·버튼 포커스를 복원한다.

## 웹 디자인 적용

아이디어 홈·상세 본문은 기존 최대 읽기 폭74rem을 중앙에 유지한다. 오른쪽 목차는 본문 바깥 여백에40px 간격으로 두며106rem 이하에서는 상단 가로 목차로 전환한다. 좁은 화면에서는 본문 앵커를 즉시 이동해 가로 목차 스크롤과의 간섭을 피한다. 여유 화면은 부드러운 이동을 유지한다. 목차 이동·선택은 실제 페이지 끝의 스크롤 한계를 처리하며 본문에 불필요한 최소 높이·빈 공간을 추가하지 않는다.

아래 제안서 디자인 규칙은 보존한 뷰어의 재사용 기준이다. 제안서 자체의 디자인은 지정된 최종 PDF를 그대로 따른다. 표지·마지막 쪽을 포함해 텍스트·사진·표·여백을 변경하지 않는다. 최종 PDF의 밝은 본문은2~13·25~28쪽, 어두운 본문은14~24·29~32쪽이다. 기존 버전의 다크 시작쪽을 코드로 덧씌우지 않는다. 일반 보기의 슬라이드 바깥 여백·하단 조작부·사이트 메뉴·내부 목차는 기존 웹 배경인 흰색을 유지한다.

일반 보기의 슬라이드는 기존 화면 맞춤 크기에서 가로·세로를 각각80%로 줄여 중앙 배치한다. PDF의 실제 페이지 경계에 그림자 `0 8px 24px rgb(0 0 0 / 15%)`를 적용하며 모서리 형태는 원본 그대로 유지한다. 전체 화면과 창 안 발표 모드는 여백을 검정 `#000000`으로 고정하고, 슬라이드는 그림자 없이 기존 최대 화면 맞춤 크기로 표시한다. 공통 변수 `--slide-preview-scale`, `--shadow-slide`, `--color-presentation-surround`에서 관리한다.

아래 CSS 값은 사이트 조작부의 기존 공통 기준이다. PDF 본문을 이 값으로 다시 구성하지 않으며 이전 출처 모달의 변수는 보존하지만 사용하지 않는다.
